# I05 | Read a specialist outcome back into the map

**Product invariant:** Think-wide supplies cross-project evidence/decisions/briefs. It does not repair or execute source projects. Trusted bounded read-only analysis remains allowed. Exact references and current authorization govern every surface.

**Evidence rule:** Documentation/fixtures, installed APIs, local real handlers, live provider/host, and deployment are separate statuses. No pass without an actual result at the identified commit/config.

## Issuance

Suggested specialty: **Any qualified teammate**. Actual owner: unclaimed until the PM assigns. Class: optional.

Attempt timebox: **25 minutes**, including the first compatibility probe. Hard stop: **September 20, 2026, 16:00 EDT**, or earlier relevant feature cutoff. These bound effort; they are not promised completion times.

Prerequisite seed IDs: T09, I02, T11. Before READY, replace these with actual integrated commits/artifacts and record the contract version. No stale issue label is sufficient.

Writable areas: src/server/providers read-only outcome handling, findings/provenance, outcome tests. Confirm actual paths against the new checkout. Shared contract/lock/auth/infra changes need the designated owner and reviewer.

## Goal

Attach an actual permitted commit/PR result to a handoff and show observed changes separately from author claims and proposed reusable learning.

## Done means

Correct repo/object linkage; merged vs closed distinguished; CI/test claims attributed; invalid source refs rejected; existing decisions not silently overwritten.

## Stop and fallback

Stop at the timebox or hard stop, or after about ten minutes of unsupported API guessing. Preserve the branch and explain the concrete blocker before changing tasks.

Leave outcome ingestion as a documented follow-on. It must not reintroduce a repair/execution or dispatch path.

## Review and handoff

Review partner: Andrew. Provide branch/commit, actual changed behavior, exact test commands/results, local/live/mock status, contract/config, remaining gaps, and next useful action. DONE requires acceptance and integration into trunk; otherwise REVIEW or BLOCKED.

Do not preempt remote MCP or core fixes. Requires spare capacity after the 15:00 recording.
