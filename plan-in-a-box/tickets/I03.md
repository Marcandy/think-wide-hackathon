# I03 | Approved GitHub issue publication

**Product invariant:** Think-wide supplies cross-project evidence/decisions/briefs. It does not repair or execute source projects. Trusted bounded read-only analysis remains allowed. Exact references and current authorization govern every surface.

**Evidence rule:** Documentation/fixtures, installed APIs, local real handlers, live provider/host, and deployment are separate statuses. No pass without an actual result at the identified commit/config.

## Issuance

Suggested specialty: **Marc**. Actual owner: unclaimed until the PM assigns. Class: optional.

Attempt timebox: **25 minutes**, including the first compatibility probe. Hard stop: **September 20, 2026, 15:30 EDT**, or earlier relevant feature cutoff. These bound effort; they are not promised completion times.

Prerequisite seed IDs: T09, I01, I02. Before READY, replace these with actual integrated commits/artifacts and record the contract version. No stale issue label is sufficient.

Writable areas: src/server/providers/github issue adapter, human confirmation route, effect receipts/tests. Confirm actual paths against the new checkout. Shared contract/lock/auth/infra changes need the designated owner and reviewer.

## Goal

Publish the exact frozen implementation brief to an authorized compatible-audience repository, with independent human confirmation.

## Done means

Destination/body/revision bound approval; no broader-audience leak; actual provider issue receipt; duplicate/replay/changed-body/unknown-outcome tests; no contents-write access.

## Stop and fallback

Stop at the timebox or hard stop, or after about ten minutes of unsupported API guessing. Preserve the branch and explain the concrete blocker before changing tasks.

Export the same reviewed Markdown for an authorized human. Mark exported, not published. Do not blind-retry ambiguous issue creation.

## Review and handoff

Review partner: Andrew. Provide branch/commit, actual changed behavior, exact test commands/results, local/live/mock status, contract/config, remaining gaps, and next useful action. DONE requires acceptance and integration into trunk; otherwise REVIEW or BLOCKED.

Do not start if it cannot fit before 15:30. A private repo connection is not enough to prove destination audience compatibility.
