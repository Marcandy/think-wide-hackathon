# T01 | Initialize the single shared checkout

**Product invariant:** Think-wide supplies cross-project evidence/decisions/briefs. It does not repair or execute source projects. Trusted bounded read-only analysis remains allowed. Exact references and current authorization govern every surface.

**Evidence rule:** Documentation/fixtures, installed APIs, local real handlers, live provider/host, and deployment are separate statuses. No pass without an actual result at the identified commit/config.

## Issuance

Suggested specialty: **Eassa**. Actual owner: unclaimed until the PM assigns. Class: core.

Attempt timebox: **20 minutes**, including the first compatibility probe. Hard stop: **September 20, 2026, 12:00 EDT**, or earlier relevant feature cutoff. These bound effort; they are not promised completion times.

Prerequisite seed IDs: G0. Before READY, replace these with actual integrated commits/artifacts and record the contract version. No stale issue label is sufficient.

Writable areas: Root manifest/lock/toolchain, instructions, .github initial check, directory skeleton. Confirm actual paths against the new checkout. Shared contract/lock/auth/infra changes need the designated owner and reviewer.

## Goal

Initialize during the allowed window, resolve the first framework/tooling baseline, and expose a shared branch plus operation design draft so both other people can begin.

## Done means

Real shared repo; actual initial package resolution or explicit blocked dependency; baseline commit; agreed field/operation meanings; everyone can obtain the same checkout. No imported app starter or fake lockfile.

## Stop and fallback

Stop at the timebox or hard stop, or after about ten minutes of unsupported API guessing. Preserve the branch and explain the concrete blocker before changing tasks.

Keep a minimal supported root project and official scaffold route. Drop optional tooling rather than creating parallel scaffolds or bypassing review.

## Review and handoff

Review partner: Marc. Provide branch/commit, actual changed behavior, exact test commands/results, local/live/mock status, contract/config, remaining gaps, and next useful action. DONE requires acceptance and integration into trunk; otherwise REVIEW or BLOCKED.

Publish the root skeleton and contract-design note as an early commit; T02 continues generation/local state. Other owners can start from that actual commit.
