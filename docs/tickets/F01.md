# F01 | Feature freeze, retest, and final rehearsal

**Product invariant:** Think-wide supplies cross-project evidence/decisions/briefs. It does not repair or execute source projects. Trusted bounded read-only analysis remains allowed. Exact references and current authorization govern every surface.

**Evidence rule:** Documentation/fixtures, installed APIs, local real handlers, live provider/host, and deployment are separate statuses. No pass without an actual result at the identified commit/config.

## Issuance

Suggested specialty: **Andrew**. Actual owner: unclaimed until the PM assigns. Class: release.

Attempt timebox: **40 minutes**, including the first compatibility probe. Hard stop: **September 20, 2026, 16:30 EDT**, or earlier relevant feature cutoff. These bound effort; they are not promised completion times.

Prerequisite seed IDs: T11. Before READY, replace these with actual integrated commits/artifacts and record the contract version. No stale issue label is sufficient.

Writable areas: Regression fixes in assigned areas, sanitized release evidence and recording manifest. Confirm actual paths against the new checkout. Shared contract/lock/auth/infra changes need the designated owner and reviewer.

## Goal

At 16:00 freeze features and dependencies, test the final integrated path and any enabled optional capability, and rehearse at 16:30.

## Done means

Current commit/image/config matches claims; required positive/negative cases recorded; optional broken modes disabled; preserved earlier recording; later recording separately identified.

## Stop and fallback

Stop at the timebox or hard stop, or after about ten minutes of unsupported API guessing. Preserve the branch and explain the concrete blocker before changing tasks.

Use the best known good commit/config/recording with truthful labeling. A broken live optional feature is disabled rather than patched by weakening a guard.

## Review and handoff

Review partner: Eassa + Marc. Provide branch/commit, actual changed behavior, exact test commands/results, local/live/mock status, contract/config, remaining gaps, and next useful action. DONE requires acceptance and integration into trunk; otherwise REVIEW or BLOCKED.

Clock gate applies even if dependencies are incomplete: enter freeze and fix the missing core, not keep adding features. Timebox is coordination/test work; each repair gets its own bounded owner.
