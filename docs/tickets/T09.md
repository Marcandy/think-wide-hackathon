# T09 | Persistent workbench and implementation brief

**Product invariant:** Think-wide supplies cross-project evidence/decisions/briefs. It does not repair or execute source projects. Trusted bounded read-only analysis remains allowed. Exact references and current authorization govern every surface.

**Evidence rule:** Documentation/fixtures, installed APIs, local real handlers, live provider/host, and deployment are separate statuses. No pass without an actual result at the identified commit/config.

## Issuance

Suggested specialty: **Marc**. Actual owner: unclaimed until the PM assigns. Class: core.

Attempt timebox: **40 minutes**, including the first compatibility probe. Hard stop: **September 20, 2026, 14:15 EDT**, or earlier relevant feature cutoff. These bound effort; they are not promised completion times.

Prerequisite seed IDs: T05, T06. Before READY, replace these with actual integrated commits/artifacts and record the contract version. No stale issue label is sufficient.

Writable areas: src/routes/investigation, src/components/behavior, convex/feature projections, handoff core. Confirm actual paths against the new checkout. Shared contract/lock/auth/infra changes need the designated owner and reviewer.

## Goal

Replace workshop memory with actual persisted investigation/decision commands. Generate a deterministic Markdown work brief from the accepted revision and exact evidence.

## Done means

Correction and prior rejection survive reload; no LLM required to save them; brief contains base commit, constraints, refs, uncertainties, acceptance, scope and hash; unsupported issue publication visibly disabled.

## Stop and fallback

Stop at the timebox or hard stop, or after about ten minutes of unsupported API guessing. Preserve the branch and explain the concrete blocker before changing tasks.

Use a simpler stable workbench and downloadable/copyable brief. Keep persistence, exact evidence and human intervention; remove animation or optional compositions, not the core loop.

## Review and handoff

Review partner: Andrew. Provide branch/commit, actual changed behavior, exact test commands/results, local/live/mock status, contract/config, remaining gaps, and next useful action. DONE requires acceptance and integration into trunk; otherwise REVIEW or BLOCKED.

Brief export does not wait for GitHub Issues write access. Handoff body must obey the audience of all consumed evidence, including private decisions.
