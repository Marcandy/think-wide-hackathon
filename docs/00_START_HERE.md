## The complete loop

Authorized repositories → global question → bounded discovery → exact evidence → tentative connection → human correction → durable decision → changed result → implementation brief → specialist coding agent.

PR/commit re-ingestion is a subsequent supported direction. It must not be fabricated into the first demo if unfinished.

The first demonstration needs two genuinely readable Git snapshots, at least one live reasoning path, a human intervention that changes the accepted result, reopening without loss of the decision, and a usable implementation brief. Prefer one authenticated remote MCP host as well. A local-only result does not establish ChatGPT or Claude.ai connectivity.

## What changed from the previous plans

- Remove repair execution, target-repository package installs, arbitrary shell, target-project tests, branch/PR creation, merge, deploy, and coding-agent dispatch from Think-wide's product tools.
- Keep trusted bounded Git inspection, literal and structural search, JIT guidance, exact evidence, reasoning, decisions, handoff export, optional approved issue creation, and later outcome ingestion.
- Replace the prebuilt starter with event-day initialization instructions and acceptance specifications. Do not copy application files or executable tests from the old launch kit.
- Replace rigid lanes with a pull queue, one active writer per person, short clocks, and explicit integration cutoffs.
- Keep hosted identity and remote MCP on an early integration track. Do not weaken authentication to make a public demo work.
- Borrow OKF's navigable metadata/index idea without adding an OKF runtime, a second database, or a document per source file.
