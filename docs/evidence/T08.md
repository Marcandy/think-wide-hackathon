## Identity and JWKS reachability

The trusted local process loads or creates a key under
`infra/.data/local-identity/signing-key.json` (gitignored; directory 0700, key 0600).
It publishes a fully written key atomically without overwriting a concurrent creator's
key. It refuses symlink keys. No private key or token is logged, committed or returned
as tool data. The ticket explicitly authorizes this ignored key path, overriding the
older AGENTS.md instruction that all secrets live in `.env.local`.

The issuer has **no listener**. It signs for one fixed local principal, an exact issuer
and an exact audience, minting a fresh five-minute token per call. Configuration must
explicitly select `local-demo` and a literal loopback HTTP Convex origin. Connected
stdio fails closed pending I01. The request-scoped client refuses redirects and maps
HTTP 401 to the contract's `unauthenticated` error.

**Docker does not fetch the host:** the backend's `THINK_WIDE_LOCAL_JWKS` setting
contains only the public JWKS as a documented data URI. The backend's
`THINK_WIDE_MODE=local-demo` explicitly enables that provider. The application never
uses an admin credential. Provisioning used the Convex CLI; no public provisioning
mutation was added.

First push rejected our initial `NODE_ENV` check in `auth.config.ts`: Convex evaluates
local bundles with `NODE_ENV=production` too. Installed bundler code confirms that
behavior. The production refusal belongs in the Node issuer/config, where it is tested.
The backend provider is opt-in via its deployment environment. Production deployment
must not set the backend's mode to `local-demo`; I04 owns that deployment configuration.
The next push and actual signed-token call succeeded; validation was never disabled.

### Reproduce local provisioning (no secret output)

From this checkout, with the existing CLI-only self-hosted credentials in `.env.local`:

```sh
bun install --frozen-lockfile
bun run convex:up
THINK_WIDE_MODE=local-demo bun -e '
import { localIssuer } from "./src/server/auth/local-issuer";
const issuer = await localIssuer();
for (const [name, value] of [
  ["THINK_WIDE_LOCAL_JWKS", issuer.jwksDataUri],
  ["THINK_WIDE_MODE", "local-demo"],
]) {
  const child = Bun.spawn(["bunx", "convex", "env", "set", name, value], {
    stdout: "pipe", stderr: "pipe",
  });
  if (await child.exited) throw new Error("Backend environment setup failed");
}
'
bunx convex dev --once
claude mcp add think-wide -e THINK_WIDE_MODE=local-demo -- bun run mcp:stdio
```

The local host registration is user-local (`~/.claude.json`), not committed.

## Automated checks and limitations

`tests/adapter/q14-same-policy-all-surfaces.test.ts` bridges only the HTTP client transport
into convex-test. A/B identities come from the existing fixtures; the actual operation
registrations, validators, authz, transactions and receipts run unchanged. This test
bridge is not evidence of JWT verification; the separate Docker/stdio calls are.

Cases: exact generated tool names; HTTP-only exclusion; unimplemented errors and MCP
`isError`; capabilities; saved decisions/replay/conflict; foreign versus missing IDs;
shared snapshot without shared investigation; unchanged victim revision; revoked grant
read/replay denial; actor/owner/principal/token smuggling at top level and inside refs;
malformed, oversized and deeply nested input. Config and real signature tests cover
explicit mode, loopback confinement, production refusals and token lifetime/audience.
A TypeScript AST scan rejects registry literals and authored schema/metadata properties
in adapter files. Generic transport routing on the registry's `read` effect is not a
per-operation restatement.

Changes outside the original adapter paths: user-approved extraction into `core/limits.ts`
and updates to the existing search/pipeline consumers; generated Convex API and operation
docs; the existing handler-binding test now derives its expected map from the registry
instead of freezing the old six-handler inventory. No T06 authorization rule changed.

`getCapabilities` has no contract field for an operation inventory; MCP tools/list supplies
that inventory. Search libraries exist, but search handlers are not bound, so searchModes
is empty. Required tree/exact-window limits are configured policy for unimplemented
operations, not evidence of a working tree or exact read. Connected capabilities fail
closed rather than guessing a WorkOS profile. I01 must extend that handler when its
provider integration is verified.

Priority 2 HTTP adapters are NOT DONE. Q14 here covers the shipped stdio adapter, shared
dispatch and direct Convex handlers; it does not claim HTTP-route acceptance.
